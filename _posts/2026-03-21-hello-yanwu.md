用了三年现成的博客主题，最后都死在同一个地方：**想改一个小地方，结果改出一堆不认识的东西**。

三月初我把旧站整个删了。这次的想法很简单：不要主题，自己写。样式丑一点没关系，但每一行都得是我知道自己在干什么的。

## 为什么还是选了 Jekyll

现在建站的选择太多了：Next.js、Astro、Hugo、Hexo，还有一堆托管服务。我先排除了两类：

- **太重的**：为了写几篇笔记装一整套 React，构建一次二十秒，不值。
- **太自动的**：一键生成、样式全包，最后又回到「改不动」的老路。

Jekyll 刚好卡在中间。它只做一件事：把 Markdown 和 HTML 模板拼成静态页面。GitHub Pages 原生支持它，推上去就自动构建，不用配 CI。

一句话总结它的模型：

> **文章是文件，页面是模板，构建就是把两者拼起来。**

## 目录就这么几个

新建一个站点，其实只需要五个东西：

```text
/
├── _config.yml        # 全站配置
├── _layouts/          # 页面骨架
│   ├── default.html   # 最外层：head + 页头 + 页脚
│   ├── home.html      # 首页
│   └── post.html      # 文章页
├── _includes/         # 可复用的小片段
├── _posts/            # 文章，一篇一个 md
└── assets/            # css / js / 图片
```

`_posts` 里的文件名必须长这样：

```text
2026-03-21-hello-world.md
```

前面是日期，后面是英文短标题，Jekyll 靠这个排序和生成链接。文件开头那段 `---` 包起来的东西叫 front matter，也就是这篇文章的「档案卡」：

```yaml
---
layout: post
title: "搭一间自己的屋檐"
date: 2026-03-21 21:40:00 +0800
categories: [笔记]
tags: [Jekyll, 建站, 前端]
description: "一句话说清这篇写了什么"
---
```

写完这一段，标题、日期、分类、标签、摘要就全有了，页面模板里直接 `{% raw %}{{ page.title }}{% endraw %}` 取出来用。

## 模板里那套 `{% raw %}{{ }}{% endraw %}` 是什么

刚接触 Jekyll 时最劝退的就是它。其实就是两种符号：

| 写法 | 作用 | 例子 |
| --- | --- | --- |
| `{% raw %}{{ }}{% endraw %}` | 输出一个值 | `{% raw %}{{ page.title }}{% endraw %}` 印出标题 |
| `{% raw %}{% %}{% endraw %}` | 做一件事，不输出 | `{% raw %}{% for post in site.posts %}{% endraw %}` 循环 |

比如首页要列出最新的五篇：

```liquid
{% raw %}{% for post in site.posts limit: 5 %}
  <a href="{{ post.url }}">{{ post.title }}</a>
{% endfor %}{% endraw %}
```

Liquid 还有个好处：你可以在里面做简单的判断和计算。我首页那几个数字，就是现算的：

```liquid
{% raw %}{% assign words = 0 %}
{% for post in site.posts %}
  {% assign w = post.content | strip_html | strip_newlines | size %}
  {% assign words = words | plus: w %}
{% endfor %}
共 {{ words }} 字{% endraw %}
```

`strip_html` 把标签去掉，`size` 数长度，`plus` 相加。粗糙，但对中文够用。

## 样式为什么自己写

直接说结论：**因为 Tailwind 和现成主题解决不了「这是谁的站」这个问题。**

我想要的不是「一个干净的博客」，而是「一间有燕子的屋檐」。这需要一些很奇怪的东西：

- 页头导航是一条电线，当前页面的燕子停在上面，鼠标移过去它会飞起来一点点；
- 页脚也是同一根电线，几只燕子错落地停在上面，越靠右越小；
- 全站背景是黎明的天色，从上到下从青绿过渡到暖白，晚上换成靛蓝的夜空。

这些东西没有现成组件，只能一行一行写。写的过程中倒是想明白一件事：**动效要克制**。第一版我让燕子满屏幕飞，看十秒就晕。现在首页只留三只，飞得极慢，剩下的交给留白。

## 一个踩过的坑

GitHub Pages 上的 Jekyll 是「锁定版本」的：它只认自己那套插件，`Gemfile` 里写了别的也没用。我第一次构建失败就是因为用了 `jekyll-toc` 这类非白名单插件。

解决办法很土：**能自己写的就别装插件**。目录、搜索、RSS、sitemap，全用原生 Liquid 和自己写的 JS 解决，反而更可控，也更快。

## 现在这个站

| 部分 | 怎么做的 |
| --- | --- |
| 生成 | Jekyll，推送到 GitHub 自动构建 |
| 样式 | 手写 CSS，一套变量管亮暗两套配色 |
| 图标 | 全是我自己画的 SVG，没有图标库 |
| 搜索 | 构建时导出 `search.json`，前端匹配 |
| 评论 | 暂时不做，想说话可以发邮件 |

如果你想搭一个类似的，其实不用照抄。**先想清楚你想让访客记住什么**，再去决定要不要一张大图、要不要动画。技术都是次要的。
